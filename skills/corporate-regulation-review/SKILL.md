# corporate-regulation-review

**适用场景**：国企内部制度/行政规范性文件审查——筛选标准、意见书结构、五类风险下限、与合同审查的差异。

# 企业内部管理制度法律审查
为国有企业审查内部管理制度（管理办法、实施细则、事权清单等）的方法论。不适用于合同审查——合同审查走 contract-review-methodology。

## 与企业制度合规深审的分工
- 本技能优先处理制度严格筛选、行政规范性文件合法性审查和事权清单权限终点检验。
- 行政规范性文件走本技能，企业制度深审走 `corporate-system-compliance-review`。同一事项涉及两类对象时，按文件性质分流，两套技能可以协同加载但不互相替代。

## 触发条件
- 审查公司内部制度/管理办法/实施细则
- 审查事权清单/审批权限表
- 审查政府及部门行政规范性文件（合法性审核/备案审查，见「行政规范性文件合法性审查」章节）
- 区别于合同审查：制度是单方操作规程，不涉及双方权利义务博弈

## 材料覆盖与声明纪律
1. 三类覆盖层级分开记：逐段通读、结构化核验（脚本扫描表格结构、空栏率、占位符、法规名称重复）、未读。交付时逐份写明，不含混。
2. DOCX 里的流程图、图片、嵌入对象在文本提取中不可见。翻过正文不构成「读完」：必须单独导出 `word/media/` 下的图片核验，做不到就明确写「图内未核验」，不写「全部通读」。
3. 大型汇编（几十万字以上）默认只做结构化核验，交付写明「未逐条通读」；需要条款号级核验时另列计划与工作量，不当场假装完成。
4. 收口固定四段：材料范围、已完成事项、未核实事项、后续办理建议。
5. 脚本产出的异常（条号缺号与重号、法规名称重复、基本信息字段不符）必须先回原文复核，再决定是否写入交付。章节标题与条文内交叉引用会造成条号假阳性，基本信息卡片与法规名称的配对随版式变化（卡片排在名称之前、或全部集中文末）会整体错位一位，把别的法规的信息当成本法规的错误。假阳性写进意见书会直接损伤整轮结论的可信度。

### 删除标准（以下类型不写入法律意见）
1. 建议性措辞：如"建议增加XX原则""建议改为XX表述"

### 保留标准（以下类型值得写入）
1. 治理边界混淆：母子公司审批程序不分、股东权力与董事会权力混同
2. 正文范围与附件清单不一致：附件（日常检查单、隐患排查清单）覆盖而正文未规定的事项（危险废物、噪声、在建项目环评与「三同时」、塑料污染等）等于责任部门与处置流程缺位，写成一条并给两种落点（正文增列相应事项，或使附件逐项对应并在附件中注明适用依据）
3. 编号异常追问内容缺失：条号重复（同一号出现两次）或章号跳号（如第六章之后直接第九章）不得只当体例问题排除，也不能在结论里以一句「建议校正」带过——须在结论中要求核实是否存在整章或整条遗漏，缺失章节可能含实体强制条款
4. 引用依据与技术标准名称／版本错误：制度援引的国家或地方标准、上位法名称与现行版本不符（把现行排放标准写成俗名、旧名，或未引直接适用的上位法），会让执行依据与处罚依据同时失准。核验回官方来源（生态环境部标准库、国资委与司法部网站、商务部规章库），不以模型记忆或搜索摘要补足；成稿列为一条，写出现行名称、编号与建议补充列明的依据，不与「措辞优化」混同
5. 上位规范对照缺项：以省级国资委监管企业合规管理办法、集团合规管理规定等上位规范逐条比对，检查组织主体、报告线、举报机制、审批附随材料是否落实。评价主体由被评价部门自行担任、所属单位对上级合规管理部门的报告线缺失、举报奖励与禁止打击报复条款缺失、报上级审核事项未附合规审查意见，属集团或国资委可直接对照条文发现的问题，优先级高于文本瑕疵
6. 报告陈述与配套材料完成状态不一致：上报集团的体系建设情况报告称已完成的手册、指南，实际存在初稿标注、封面旧日期、占位符未填、缺章、公司名称写错时，先核材料再定意见，并提示集团索取原件时的落差风险

### 数量控制与输出形态
正式《法律分析建议书》最终问题 2-4 条。超过 5 条说明筛选失败。

## 意见书格式
关于《[制度全称]》的法律分析建议书
[开篇段：收悉声明 + 法律依据 + 审查对象，合并为一段]
第一部分  审查概述
[一段：制度结构概述 + 核心问题预告，不列全部问题]
[每个问题独立成节：标题→分析(1-2段)→建议(1段)]
[不要分"高风险/中风险/低风险"层级，直接列问题]
第三部分  审查结论
[四段标准免责声明 + 一段后续服务提示]

### 格式铁律
- 结论不下"本制度可以施行"等商业判断

### 五类确定性风险下限（先定审查优先级）
| 规则 | 风险 | 等级 |
| ND-001 | 疑似自行设定或加重行政处罚 | 高风险 |
| ND-002 | 疑似自行设定行政许可、强制措施或强制执行 | 高风险 |
| ND-003 | 疑似自行设定收费、保证金或其他强制缴费义务 | 高风险 |
| ND-004 | 疑似限制市场准入、退出或跨地区经营 | 中风险 |
| ND-005 | 疑似扩大行政检查、裁量或不利法律后果 | 中风险 |
规则只确定审查优先级，不替代对上位法授权和属地规则的核验。发现"罚款"等措辞只触发高优先级核验，仍须结合有效上位法授权、文件层级和属地规则判断。

### 边界纪律（不可逾越）
- 程序材料缺失只标"待核验"，不得写成程序违法；文件中没有记载的程序事实不能推断为未履行——应要求提供合法性审核、征求意见、集体审议、发布或备案材料

### 审查维度与台账结构
法律数据库不可用或结果不足时，记录官方来源降级范围；来源冲突、历史版本不明或地方规则未可靠取得时一律列为待人工确认。

### 输出
- XLSX 审查台账：供逐条复核和整改流转（每项结论须有文件定位）

## 事权清单审查专项
事权清单（审批权限表）的审查重点不同于普通制度：
1. 母子公司边界：子公司事项是否被纳入母公司内部审批链条（混淆治理边界）
2. 党委会定位：党委会前置研究是否越位替代经营决策（如采购结果确认由党委书记审批）

## 工作流
1. 清点材料并逐份记录覆盖层级（逐段通读／结构化核验／未读），读完再动笔（见「材料覆盖与声明纪律」）
2. 二轮筛选（按本技能保留/删除标准过滤，压到 2-4 条）
3. 按模板格式出建议书

## 反模式
- 问题清单过长：超过5条说明没做二轮筛选
- 先写后查模板：必须先查历史模板再动笔
