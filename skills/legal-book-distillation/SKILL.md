# legal-book-distillation

**适用场景**：拆法律实务书/实务档案→升级现有技能（不新建技能）。触发：拆法律书、拆档案/原档、继续拆（法律）、书→技能映射。

## 引文、页码与条号：拆书中期必做的三道核验
拆书不是“提取完就装”，每条规则都要能回原文。三道核验不做或做错，后面全部白做：判级错→标注错→装进技能的“逐字引文/摘编”标签就是假的。
1. **基线优先**：结构化 DOCX 正文 > 单册 PDF 文字层 > 合集 OCR 文字层；切分只认正文标记（如 `[第N号]`），目录标记只有标题。判级前先抽 5 条已知逐字引文验基线，命中率低就先换基线。
2. **禁止自动改字**：与原文差 1–3 字时，先判方向——形近讹误多为原文错、候选对（入↔人、间↔问）。只改标注（`source_quote`→`source_digest`＋`quote_status`）并出待核清单，引文文本不动；按窗口重建句子会丢标点、拼错句。
3. **体例决定“一条”的边界，也决定漏检的核对单位**：教材／专著按章、争点体／问答体按单元编号、文书范本按文书类型。争点体与问答体必须先用目录抽出单元清单**逐号核对**（只核总条数会掩盖整段漏提）；分块派活时把号段写进指令。

### 0. 侦察（每本新书）
1. 检查 `ocr结果/` 是否已有拆分（`_split_` 前缀目录 = 百页一册的 PDF 分块 c_0000-0099.pdf，可直接用作分块源）。

### 2. 阶段 1 — 5 提取器并行
framework / principle / case / counter-example / glossary 五个提取器（prompt 在 cangjie-skill 的 `extractors/`）。本环境 delegate_task 的并发上限按工具说明里的 `max_concurrent_children` 取（本机配置为 10，历史笔记里的“上限 3”已过期，不要据此把批次切细）；只在大书分组时才需分批部署。**大书（>20 个 part 文件）必须分组**：每任务 13-14 个 part 文件（600s 硬上限内稳定值，见 Pitfalls 超时治理条），全书按 part 数 ÷ 14 分组，5 提取器 × 组数 = 总任务数，3 个并行交错分批部署（如 3 组 × 5 类 = 15 任务分 5 批）。任务描述写死文件范围 + 每文件最多 2 次调用。

### 2.5 系列辑刊批量铺开（同一丛书多辑，体例一致）
1. **任务简报用生成器，不手写进 context**：项目内放一个简报脚本（`python _brief.py <辑> <提取器>`），把该辑的源材料范围、目录原文、读取方法、提取范围、引文硬规则、输出格式、自校验与汇报要求全部生成出来；delegate_task 的 context 只写"先运行这条命令，把输出当作你的任务简报逐条遵守"。手写长简报会因载荷过大被截断，逐辑事实（年份、part 范围）也容易写错。生成器读 `toc_sample.txt` 等可选文件前**必须判存在**——纯 OCR 辑没有该文件，会让生成器直接抛错；此类辑的简报还要注入"本辑为 OCR 文本、无逐页标记，页码只能标到段（如 `part_02（段起点 PDF p101）`），不得编造页号"。
2. 系列专属栏目结构、分块与引用约定写进该系列的 references 文件，后续各辑先读它再动手。
3. **建《缺口与待补清单》（项目根下 .md），把子代理自报的缺口落成可追办项**——子代理会在汇报里主动写"为控条数封顶未单列 X 项""某几个区段仅定位抽查未逐字通读""本辑无某栏目素材"。这些若不落盘就静默丢失。清单分三类记：①**真缺口**（有实质内容因条数上限未列，可定向补提，记来源篇名）；②**源材料所限**（该辑本无对应栏目/文章，不算遗漏，不补）；③**粒度受限**（OCR 辑只能标到段、某几段未通读）。阶段 1 收尾时先过一遍清单再动手补，不要重跑整辑。
4. **补读/补提任务的契约要写全**：针对“某区段仅索引抽查、未逐字通读”的覆盖缺口，只发定向补读任务（不重跑整辑），context 里写死——①只读指定区段，不得抽样；②新条目**编号从前一份产物最大编号连续续编**、字段格式与既有条目一致；③**不得改动既有条目一个字**；④头部补一句“某区段于何日二次补读，新增第 N–M 条”；⑤逐字读后确认无新增时，**同样要在头部写明“已逐字补读、无新增”及理由**（否则这一段的覆盖状态仍是空白）。改既有文件前先留 `.bak_*` 可回退副本。
5. **批次收口出一份核验报告（落项目内 `stage15/`），不要只在对话里报数**，固定含五项：①**条数矩阵**（逐辑 × 五类，脚本按 `^- id: ` 计数）；②**逐份覆盖声明汇总**——把每份候选头部自报的“未逐字通读区段／源材料缺失”抽成一张表，**未声明者标“未声明”**（这是区分“文件合格”与“覆盖穷尽”的唯一台账）；③**层级标注统计**（按“域外／学理／地方／课题组／非司法解释／拟议”等关键词计数），供阶段 1.5 过滤；④待办与异常清单（域外条目、地方建议、非执行域条目、源缺辑次、舍弃清单）；⑤复核命令与结果。每项结论后附可复现的命令或文件路径，无法核实写“未能核实”，不推测。

### 3. 阶段 1.5 — 三重验证与分域速查编制
**续编与重建的常驻验收规则**：把人工确认的跨册归属、互见指针和分歧保留决定作为独立数据保存，并接入生成链（在生成后、写盘前统一回填，定位命中不唯一即整批停止、幂等可重跑）；不得只改生成后的合并稿，否则下一次重建会覆盖审阅成果。按“域名＋主条 id＋标题”回填，定位缺失或不唯一即停止，不按历史行号猜写。装入前连续重建两次，核对内容一致、全部指针目标成立、剥离新增标注后的正文未变、既有修正未倒退；项目合并稿通过不代表技能库装入件已经更新。术语同名只形成待审组，不直接认定同义；逐项确认定义与来源，未核实不得默认标成现行规范。

### 4. 映射阶段（替代 cangjie 阶段 2-4）
- 直接可用清单 → contract-review 系技能（methodology / delivery）
- 风险维度新增 → 甲方利益审查技能
- 决策框架 → legal-opinion-delivery（"给建议而非只提示风险"）
- 语言规则 → 合同语言审查
- 流程方法 → 审查流程标准化

## Verification
- **核验脚本的基线要取主源（分册），不取上一版成品**：拿上一版合并稿当基线，分册一改就整片报「正文变化」，而误报会诱使人把刚做的正确修正回滚。正确做法是把合并稿去掉标注后的表行与**全部分册**的行多重集比对，并**排除每节重复出现的表头行**（表头按段重复，天然对不上），只比承载条 id 的数据行。基线选错与修正做错都会让验收失去意义。
- **“没查出问题”的结论同样要报，并写明覆盖范围**：逐条核完确认零错误的辑／域要显式写出“已逐条核对 N 行、真错误 0”，否则读者无法区分“核过没问题”与“没核”。**候选层讹误与速查层错误分开说**——候选里有过 OCR 讹误而未传播进速查时，只报“速查零错误”会让人误以为源文本也干净。
- **台账里写的“待办”也要先核它是否真实存在**：续办台账上“某批页码尚未回改／某项尚待补”这类条目，若是凭印象补的，会把已经正确的产物拖进返工。写待办前逐条回文件确认（页码类直接打开对应候选条看实际值），核实不成立的删掉并在台账注明“经核不存在”；发现自己上一轮误报要当场更正并说明，不要把错待办留给下一轮。反之**已办结的旧待办要就地标注办结与依据**（哪一轮、以什么产物办结、核验结论如何），不能只在新段落里记一遍——旧行原样留着，续办时会照旧清单把做完的事再做一遍。**在台账里插入新条目前，把充当锚点的那一行完整写回替换文本**——`patch` 的 old_string 若取了下一条目的标题行而替换文本没把它包含进去，标题会被吃掉、两条并成一条（同一次维护里连犯三次才发现）；插入后回读该段确认标题仍在。
- 映射方案交付前：逐技能核对"该技能现在有什么、缺什么、加什么"，不写空泛建议
- **落点按章切片，不重复投放**：一本书跨两个消费技能时（如侵权＋劳动），按小节切分成两份 references，同一批规则只进一个技能；安装件重写头部（来源、编制与核验状态、可靠性、未覆盖范围），消费技能 SKILL.md 只加一行路由，改前备份到项目外的 backups 目录，改后核对引用文件是否都存在。
- **速查行统计按表头判列数、先剔辅助表**：同一批速查里 2 列（规则｜要点）与 3 列（规则｜要点｜来源）并存，另有关键标准速记、校验（按分组统计）等辅助表；按"所有 `|` 行"统计会把辅助表和表头算成规则行，让"无出处行""列数异常"虚增。列数逐表按表头判，表头含 关键标准／校验／统计／速览 的整表排除后再统计。
- **速查行与候选条目数恰好相等时，用一对一最优匹配补 traceability**：行数＝候选条目数时做最大权匹配（匈牙利），再抽 3–5 条最低分的回原文比标题与出处确认；相似度低不等于配错（标题被压缩改写时中位 0.76、最低 0.13 仍为真匹配），判断看内容不看分数，且必须接受"低分需人工确认"这一步不能省。
- **生成索引表时表头与列序必须同源**：表头写"分册｜内容"、行数据却是"内容｜文件名"，读回时 7 行都在、不报错，但列语义已经反了。生成后读回 2 行逐列对表头，不只看行数。
- **子任务自报「自检通过」不构成核验**：子代理只看得到自己那一段，跨段冲突（重号、同题重复、章归属错）与它无关；合并后必须自己跑字段完整性、页码是否存在、案号回原文、id 唯一性四类脚本，跑过才算。
- **安装进技能时**：文件名避免含「·」（linter 会在点号处截断、误报 dangling-reference，不必为它改名）；每个安装件头部写清来源／编制与核验状态／摘编声明／未覆盖边界；SKILL.md 加一行路由；改前把 SKILL.md 与被覆盖的旧件备份到 `backups/<主题>_<日期>/`。
- **候选文件前缀在项目内必须唯一**：同一个项目里多本书的候选文件用互不重叠的前缀（如 `gsf-p*` 与 `gs-p*`），build 只 glob 本书前缀。前缀撞车会把另一本书的条目一起吃进 build，报出来的却是「越出拆解范围／页码异常」这类假错；顺着报错放宽阈值，两本书就被混编进同一批速查。
- **案号核验要连字母混淆一起归一**：文字层会把数字读成字母（`2Ol5`＝2015、`c2007)`＝(2007)、`浙雨`＝浙甬、`笫109`＝第 109）。只归一空格与全半角括号，会把整批真案号误报成编造；改为「易混字符归一（O→0、l→1、S→5、Z→2、B→8）＋ 数字串与非数字片段双命中」，人工核对过的字形变体设白名单并在条目内注明原文写法。
- **比较法教材要隔离两套法、按需节选**：凡属美国／特拉华规则的 `effect` 一律标「美国法（比较法参考）」，美国判例不单独出 `case` 条，校验脚本加“提及美国法而 effect 未标比较法即报错”；教科书整本拆会把学理切碎，只拆与办案直接相关的章节并在册头注明未拆范围，分册名按实际内容定、不照抄原书篇名。
- **旧书规则出条不等同可直接引用**：民法典前的规则按原文出条，但凡属被民法典及其解释重写的领域，先核现行条文并在 `rule` 末尾写衔接（例：婚后父母出资购房，旧解读「首付只赠与己方子女」已由婚姻家庭编解释（一）第29条改为「有约定从约定、无约定按共同财产」）。
