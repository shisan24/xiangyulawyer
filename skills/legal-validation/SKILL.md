# legal-validation

**适用场景**：核验法律成果的规范、案例、时间适用、引文和事实证据链；区分已核验、待核验、来源不可用与冲突。

# 法律来源与适用校验
**可计算法律断言沿用同一条状态链，不新增并行标注。** 对能以确定性方式复算或约束的断言——日期与期间、金额与比例、条款间结构化冲突——输出结论时仍只用上文六态，不另立一套“证据等级”状态与之并列。推导过程单列一条审计轨迹（每次检查返回有序的步骤记录），每步标注该步结论的得出方式，仅作**细目**使用，按下表唯一映射并入六态：
| 步骤得出方式（细目） | 含义 | 是否构成核验 | 并入后的正式状态 |
| DETERMINISTIC | 由算术或逻辑直接得出（日期运算、精确比较、可判定的约束求解） | 是 | 仅此类步骤可支撑 `verified_current` / `verified_historical` |
| PARSED | 从结构或查表读得（如时效期间表），非权威存在性证明 | 否 | 查表源本身已核验时方可 `verified_*`，否则 `pending` |
| INFERRED | 由模式或关键词推出，边界情形可能出错 | 否 | `pending` |
| UNSUPPORTED | 该输入无法建模 | 否 | fail-closed：记 `pending` 或 `source_unavailable`，不得放行 |

## 独立复核的组织与裁决
复核心文书时给**文件路径＋待核事实**，不粘贴手工转写的全文。转写会制造伪缺陷：复核者据粘贴文本判定“此致与法院名同行、版式不合规”，而原件里两者分属两段（受文机关名顶格另起一行）；据“原告及其岳母某甲”判定亲属关系无出处，而该表述正是起诉状原文。复核者交回的问题清单先过一遍“原件是否确实如此”，**格式类与来源类发现一律回原件核对再收口**。
**复核结论一律回原文裁决，不直接转述。** 复核者会给出误报：把印章压盖的落款日期读成另一个日期、把由样式自动编号渲染出的标题判为「缺号／跳号」、把按合并列做键得出的负数当真差异、把「未见扣减行」当成「未发生扣减」（扣减可能逐格不规则落在明细单元格里）。裁决时逐条重读原件——日期用高倍局部渲染复读，编号与着色按 PDF 的 span 颜色和 `style.name` 复核（不按段落文本前缀，编号不在文本里），金额差额用两条独立路径复算。成立才进收口报告，误报单列一节并注明复读方法。
收口用「已解决／仍存在／有变化」三栏，并区分「复核员发现且经我复核成立」「复核员误报」「复核员发现但我复核后维持原判断」。同一模型独立上下文的复核只称独立复核，不称第三方评审，不以多模型一致证明法律正确。
