# legal-document-workflow

**适用场景**：法律文书起草、修改、排版和交付；按用户指定阶段处理，保留最后手改版，核验来源与文档完整性。

## 修订前的版本基线与谱系确认（每次修订既有文书时）
1. **压缩稿回补最新内容：不用逐段 diff，用关键点核验表**。精简稿/压缩稿是对完整稿的改写压缩（常压到三成上下），段落不一一对应，逐段比对输出全是噪声，会让人误判「内容大量缺失」而重做整篇。做法：从完整稿提取可枚举的硬锚点（法条与司法解释条款号、日期、金额、单位名称、合同条款序号、文件编号），逐项在精简稿全文做包含检索，列出缺失清单，再**按完整稿原句**补回并适配精简稿的上下文衔接——凭记忆重写会引入未核验的表述，也会让同一事实在两份对外文书里出现不同写法。补入后复查锚点齐备、段落数与字数变化合理、格式闸门重跑通过。

### 版式与页数控制（DOCX 改稿）
- **以基线 DOCX 作格式模板逐段复制**：deepcopy 目标段落 XML，替换首个 `w:t` 的文本、删掉多余 run，插到 `sectPr` 之前；不要新建 Document 重排，重排会丢字体、缩进、行距与 `keepNext`（标题不孤行），也丢掉原件的页码设置。
- 读回逐段核对字体、字号、首行缩进、行距与基线一致，再渲染看首末页；只跑文字闸门不渲染，不能声称版式通过。

## 按清单出修订版（对外文书二次成稿）
1. **先 dump 再改**。`python-docx` 的 `d.paragraphs[i]` 索引在插入段落后即变化，插入统一放最后执行；改前逐段打印 `style/alignment/runs` 与全文，确认目标段再动——索引错一位就会把整段小标题覆盖掉。
2. **分步落改，不写一个大脚本**。一次要改二十来段时，把文本按 2～3 段一组写成多个小脚本，每个脚本读文件、只改自己那几段、再存回，顺序执行，单个脚本控制在 2KB 上下。单步失败能直接定位到哪几段没落地，重跑那一个即可（读-改-存是幂等的），也不会因为一次载荷过大卡在传输上。全部改完再统一 dump 一遍全文回读。
3. **run 级替换保格式**。新文本写入 `runs[0].text` 后删除其余 run（必须 `r._element.getparent().remove(r._element)`，只置空文本会留空壳）；页眉、页脚、logo、字体、对齐一律不动。整段 `p.text = ...` 赋值会丢格式。
4. **三项验证再交付**：逐段读回比对（段数、编号连续、无空段）；禁用符号扫描用 `p.text`，不要用 `<w:t[^>]*>` 正则（会误匹配 `<w:tab/>`，引号计数出现假阳性）；Word COM `ExportAsFixedFormat(路径, 17)` 导 PDF，核页数与首页、末页、新增段所在页的页码、署名、落款。
5. **目录只留成品**，生成脚本、渲染页、读回记录收进子目录，不与交付件混放。

### Markdown 源稿生成对外 DOCX（净稿）
- 行内 `**加粗**`：按 `text.split('**')` 交替设 run 的 bold，段落文字里不得残留 `*`。只剥标记不设加粗，重点会整段消失。

## 复核指令的执行口径（只报不改）
1. **全轮只读**：不改正文、不改格式、不留副本、不覆盖任何版本。复核报告中的修改建议一律以文字呈现，不落进 docx。
2. **区分事实层级**。第三方报告中的转述、单方函件中的转述、仅有 OCR 未见原件的文件，分别标注来源层级并建议补取原件，不与原件同等写成簿册事实。
3. **报告里的计数、姓名、单位名必须当场算、当场抄**。写「N 处」「N 条」前用脚本或检索现算一遍，不用通读印象累计；人名、单位名、数字逐字复制自回源结果，不复述记忆。复核报告里的一处计数或姓名错误会连带削弱全部结论的可信度，也会被追问「核实清楚」。

## 出稿前的跨文件一致性收口（同一事实在多份文件中）
1. **台账本身不一定自洽**：同一份欠费台账的不同 sheet 可能给出不同的「已缴／欠缴」（一套按合同周期记、一套按自然月记），由此推出三个数。逐 sheet 核对，把差异定位到**具体哪一笔款的入账归属**，不要默认表与表之间已经对上。
2. **期间与金额必须自洽**：「自 X 起至 Y 止，累计欠 A 元」要能对上 X–Y 期间的每月标准与已付期数；对不上就改成可核对的写法（应缴／实缴／欠缴三段式），再谈精简。
3. **兜底句分层用**：内部方案可写「具体金额以双方对账核实为准」；对外函件不写这类示弱句，直接在文内列明应缴、实缴、欠缴三个数。

## 压缩与「保留原意」的边界
被问「内容是不是太多了」时，分两层答：**内容层**（结论、要件、依据是否齐全——缺的不删）与**形式层**（段落改表格、合并同类项、措施清单独立成附件），再给「正文＋附件」的拆分建议；不要一上手就砍结论或砍依据。同一文件同时承担「判断」与「操作清单」两种职能时，拆开交付比压在一份里更清楚。

### 外部模型草稿落地为 DOCX 的操作序列
**克隆段必须用元素引用改文本，不要事后按文本回扫定位**：克隆段与源段文本相同，插入后再遍历段落按 `startswith`／包含关系找目标，会先命中标题段、致送段等靠前的段落并把它们覆盖（一次实操把标题与致送行都替换成了新句子，只能从备份重建）。写法是保留克隆元素的引用（`clone = copy.deepcopy(src._element)` → `target._element.addprevious(clone)`），直接在该元素内处理 `w:t`：首个 `w:t` 写入新文本并设 `xml:space="preserve"`，其余清空；改完读回逐段断言首段标题、致送行、原文其余段落文本未变。

## 科学分段：一段一义，不按字数机械拆
拆分操作（python-docx）：取该段文本按切点串切为多块，首块留在原段，其余块 `copy.deepcopy(原段._element)` 后用 `addnext()` 链式插入并替换文本，格式随原段继承；切点必须落在句号或编号处，不从句子中间断。拆分后读回抽查切点衔接（前段末句完整、后段首句可独立成读），并复核段数变化与渲染页数。
「段落科学分级」「每个点下面没有分层次」是分段指令的下一级，与分段同批处理：**分级＝全篇同一层级用同一编号体系、分点（其一／其二……）一律独立成段且粒度一致**——同一文档一处段内并列、一处独立成段的，即判不合格；**点内分层＝每个「点」下面还要有显式层次**——论证型节把并列层次编号（其一……其四）逐层成段，评估型段落用「事实方面／法律方面」「……有二：一是……二是……」切分。操作顺序：先扫描全文分点、列出「段内多点」清单，统一拆齐，再复扫「段内多点＝0」与段长上限，渲染后抽查切点衔接。

## 成果文件落位（先临时工作区，确认后进案件目录）
**覆盖工作文件被拒时改走 patch 或另存新名**：`write_file` 只认本任务内对该文件的完整读取；若其间曾用 offset/limit 分页读过它，即便随后又整读一次，覆盖仍会被判「未看全」而拒绝。此时不要反复重试，改用 `patch` 做定点改，或另存带区分后缀的新文件名并在交付说明里写明新旧对应关系。整篇重写时还有第三条路：先 `cp 原名 原名-旧版<日期>.md && rm 原名`、再对同名路径 `write_file`——旧版留在同目录作备份，交付说明里注明旧版文件名。

## 交付包打包与下游制品同步
多版本文书＋证据目录＋成册＋证据源件成套交付时：
1. **包内容核验不能只看文件数与大小**：从 zip 直接读出关键文件核对——docx 用 `python-docx` 读 `BytesIO(z.read(name))`、PDF 用 `fitz.open(stream=bytes, filetype="pdf")`；断言最新修订句在位、应删句为零、成册页数正确，确认包内确为更正后版本。
