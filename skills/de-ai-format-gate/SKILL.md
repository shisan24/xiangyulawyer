# de-ai-format-gate

**适用场景**：DOCX输出格式闸门——破折号/ASCII引号清零+文本层八维核校+全料审查。触发：DOCX出稿前检查、文书细节校对。

# 同类公文AI腔词："未予明确/未予界定"改"未明确/未界定"、"模糊"改"不如…明确"
forbidden_words = ['口径', '未予明确', '未予界定']

## 加粗核验（run 级加粗对表源稿，含平行版本一致性）
交付前对 run 级加粗做一次专项扫描：`rPr` 含 `w:b` 且 `val` 不为 `'0'/'false'` 的 run 即加粗（`from docx.oxml.ns import qn`；只看 `run.bold` 会漏掉显式取消等中间态）。三条判据：
1. **与源稿对表**：由 MD 源稿构建的文书，源稿残留的 `**…**` 标记即加粗设计底稿（`re.finditer(r'\*\*([^*]+)\*\*', md)`）；DOCX 实际清单与它双向取差集，多出的、少掉的都处理，不得只修一个方向。
2. **平行版本一致**：仅抬头/请求不同的多份（多机关版本）必须逐份扫；同一段落加粗与否完全一致，某份粗、某份不粗＝分头改稿留下的走样，不是版本差异。

### 分组规则
1. 只有证明对象、法律要件、责任后果或论证方向发生变化时才新增小标题。仅仅换了一份证据、换了一个例子，仍服务于同一结论的，放在同一小标题下。
2. 小标题本身不承载未经材料支持的新事实，不改变原有实体内容。先定标题所统领的证明对象，再核对其下每段是否都服务于该对象。
3. 内容锁定优先于版面优化：新增、删除或改写小标题前保存正文基线，生成后移除新增标题并比较正文段落顺序和全文字符，确认事实、证据编号、金额、日期、法条、引语和结论均未变化。

### 标题语言与标题密度
1. 一级标题统领一个主张，小标题统领一个分支。标题应让读者仅看标题就知道本段将证明什么，但不把多个并列名词机械串在一起。标题可以适度完整，不以追求最短为目标。
2. 标题语言应与正文结论一致。正文只证明“现有材料不能证明”的，不把标题写成无条件的事实断言。对存在限定条件的判断，保留“不能证明、不能当然、缺乏基础”等必要范围。
3. 小标题不是每个正文段落的标签。只有证明对象、法律要件或责任后果发生变化时才新增。通常一个一级争点保留零至两个小标题，已有主标题已经覆盖的内容，不再设置重复小标题。需要控制篇幅时，优先删除与主标题同义的重复小标题，不删除其下的独立论证。

### 页数收束与重复论证
1. 先识别重复的事实、证明目的和结论。优先删除重复总结、重复的结构提示、与主标题同义的小标题、已经在前文完成证明的再次归纳，以及不影响法律效果的纯结语。不得删除唯一出现的事实、证据编号、金额、日期、法条、原话、责任要件或诉讼请求。
2. 相邻段落服务于同一证明目的时可以合并，但不得把多个独立法律问题揉成一句长句。合并后仍应保留自然句号和可读的逻辑断点，单段通常控制在约170字以内。
3. 页数接近目标但仍多出一行时，先检查是否存在重复标题、重复结论或可删除的格式性套语，再决定是否删减。不得为了让日期、落款或最后一行回到上一页而改动核心事实和法律论证。
4. 每轮收束都要做正文白名单diff：除明确删除的重复内容和获准的标题调整外，事实、证据、金额、日期、法条、引语和诉请不得发生无记录的变化。保存后用python-docx读回，再删除旧PDF并用Word/WPS重新渲染确认页数和分页。

### 验收
加标题或收束正文后必须重新用 python-docx 读回：检查正文最大段落长度、正文首行缩进、标题是否仍为 `Normal`/正文样式、标题是否非加粗、标题数量是否与论证转折相称、落款是否右对齐。若使用 `keepNext`，单独记录其用途为防孤行，不得把它误判为标题样式。再用 Word/WPS 导出新 PDF 逐页查看，重点检查小标题孤行、正文跨页是否造成语义断裂、标题是否因不加粗而与正文融为无法辨认的长段，以及末页落款是否被挤到下一页。旧 PDF 必须先删除，不能用旧渲染结果验收新 DOCX。

## Pitfalls
- 「以为自己看完了」是最大陷阱。大PDF分页OCR时容易在中途插入其他操作，导致漏页。必须等批处理全部完成后再读结果
  **根因**：python-docx的`run.text.replace('"', '"')`不区分左右引号，统一替换为左引号。必须手动配对。
- **规范性文件正式名称内的破折号**：名称本身含「——」（如《监管规则适用指引——法律类第2号》）时，闸门会判为残留。处置是改写为括号形式（《监管规则适用指引（法律类第2号）：……》），保留名称可检索性与完整性，不删字、不缩略、不为过闸把名称拆成两句。这是名称写法调整，不是删改引用内容。
  **模板继承的蓝还会落在自动编号上**：由模板复制生成的文书，Heading 段落的编号前缀（如「第二部分」）随段落与编号定义着色，只改 run 颜色会漏。修复三处同改：每个 run 的 rPr、段落标记 `w:pPr/w:rPr` 的 `w:color`（编号取此处）、`w14:textFill`。**定位这些段落按 `style.name`（Heading 系列）或按渲染后 PDF 的 span 颜色全集，不要按段落文本前缀**——编号不在段落文本里，用「以『第』开头」筛选必然漏掉文本为「补充资料清单」、渲染为「第二部分 补充资料清单」的那一段。通过判据：重导 PDF 后 span 颜色只剩 0x0 与页眉页脚灰。
- **在既有文书上增量加句后必须同批重导 PDF 查页数，孤页按「先删格式性空段，再对齐同批行距」处置**：一页函件加一两句就可能把落款挤到第二页，末页只剩落款两行（`pdf_geometry_check.py` 报「稀疏页(<4行)」即异常）。处置顺序：① 删落款前的空白间隔段（纯格式元素，先动它）② 仍超页再把行距对齐同一套其他文书（同套里既有 19 磅又有 21 磅时统一，不新造参数）③ 以上都不足以解决才考虑删内容。不得靠缩小字号、压缩页边距或改写法律论证把落款拉回上一页。**平行版本（除抬头与被指内容外应逐字相同的多份）要同批处理并保持段落结构一致**，只修其中一份会留下结构走样；若确只改了一份，在交付说明里写明。加句、导 PDF、看页数三步同批完成，不以上一轮的页数结果放行。
- **二次编辑后必须重跑闸门**：补写或插入段落（新增叙事段、补列事项、调整小标题）是分号、破折号、引号配平的新高发区；任何局部修改后重跑生成侧自检＋全文扫描，不以「上一轮已通过」放行。
  1. **改表后回头扫正文描述**：删掉表格某一列或正文某一节后，正文里介绍该列该节的句子会留下过期描述（「每项列明调查事项、需取得的资料与核查方法及关注要点」——核查要点列已删）。特征是名词组合与成品实际结构不一致，手工通读最易漏；按被删栏目与章节的名词做一次 grep 即可定位。
  属性清洗写盘会偶发 `PermissionError: [WinError 5]`（刚 save 完的目标文件被索引或预览进程短暂持有）——替换写成重试循环（间隔约 1 秒重试数次），失败再退到「删目标＋改名」。一次失败就放弃的脚本会边报告成功边让文件带着属性出厂。扫描命中不等于要删：法条与业务术语会误命中（「修订」「登记」「内部」在正常语境里大量出现），逐条看过再改。
- **两段式标题不要把引号对拆在两段之间**：标题排两行、且只有两个标题段时，把中文引号闭合在第一段（`关于“××规定”的` ／ `法律意见书`，与母版同构）。写成 `关于“××规定` ＋ `”的法律意见书` 会让左引号落在首段、右引号落在次段，闸门的逐段配平检查直接报错——全局左右计数相等掩盖不了这种跨段错位，且这类错误在只做全局配平的旧脚本里查不出来。
